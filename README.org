#+AUTHOR: yoshzucker

* org-dayflow

Simple day-flowing timeline view for Org.

org-dayflow displays Org tasks on a compact horizontal timeline with a density sparkline and aligned task titles. It is designed as a focused, visual complement to =org-agenda= rather than a replacement.

What you pick is a *period* — a month, a quarter, a year, a decade — and the period decides what one column stands for and how many columns to aim for. Nothing shorter than a month: the hours of a day and the days of a week are what =org-agenda= is for.

The default is =month=: where each piece of work runs and where it is due.

| Period | One column | At eighty columns |
|--------+------------+-------------------|
| =month= | a day | twenty-six days |
| =quarter= | a week | about four months |
| =year= | a month | a year |
| =decade= | a year | ten years |

The grid fills the window, so a wider one shows more of the same period.

A task is drawn whenever any of it is in view: its row starts where its work does (the earlier of SCHEDULED and an active timestamp) and the box runs to its DEADLINE.  An open task whose dates are behind it is still owed, so its box runs on to today, as the agenda carries it forward.

** Features

- Four periods from a month to a decade, each sized to the window; a month is the default
- =org-dayflow-exclude-files= keeps files the agenda reads — a mirrored calendar, say — off the timeline
- A demo mode (=M-x org-dayflow-demo-mode=) that generates a few weeks of work, dated from today, so the view can be looked at before anything is configured
- Headings drawn across their children's dates, and folded with =TAB= like Org: a folded heading keeps its line and a ◆ on each deadline under it
- One-line load sparkline (Unicode block glyphs ▁▂▃▄▅▆▇█) showing task density per time unit; color encodes deadline / scheduled / active (and done)
- Rich interactive filtering (tag, todo, property, category, regexp) with include/exclude and "filter at point"
- Saved queries + per-session history
- Follow mode, direct editing (schedule/deadline/todo), and navigation that feels like =org-agenda=
- Window management modeled after =org-agenda-window-setup= (including restore after quit)
- Zero external dependencies beyond Org and Emacs

** Installation

*** Using straight.el (recommended)

#+begin_src emacs-lisp
(use-package org-dayflow
  :straight (:host github :repo "yoshzucker/org-dayflow")
  :after org
  :config
  (global-set-key (kbd "C-c f") #'org-dayflow))

;; Or as a key of the agenda dispatcher, `C-c a d':
;; (add-to-list 'org-agenda-custom-commands
;;              '("d" "Dayflow" (lambda (_) (org-dayflow-display)) ""))
#+end_src

*** Using package.el + Git (manual)

Clone the repository into your =load-path= and require it:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/org-dayflow")
(require 'org-dayflow)
#+end_src

** Quick Start

=M-x org-dayflow= (or bind it) and press =d= (or =RET=) for the default period, or =m=, =q=, =y=, =D= for a month, quarter, year or decade.

In the Dayflow buffer the most important keys are:

| Key | Command                        | Description |
|-----|--------------------------------|-------------|
| =q=   | =org-dayflow-quit=             | Quit (restores windows if configured) |
| =r=   | =org-dayflow-refresh=          | Re-render the view |
| =n= / =p= | next / previous item        | Move between tasks |
| =RET= | =org-dayflow-switch-to=        | Jump to the Org heading |
| =SPC= | =org-dayflow-show=             | Show heading in other window, cursor stays |
| =TAB= | =org-dayflow-toggle-fold=      | Fold / unfold the row at point |
| =S-TAB= | =org-dayflow-cycle-depth=    | Show one level more; after the deepest, the top only |
| =/=   | =org-dayflow-filter-dispatch=  | Filter menu (org-agenda-like); =s= selects presets |
| =]=   | =org-dayflow-filter-dispatch=  | Same as =/= (legacy alias) |
| =f=   | =org-dayflow-toggle-follow=    | Toggle follow mode |
| =s= / =d= / =t= | schedule / deadline / todo | Edit the task at point |
| =+= / =-= | zoom out / zoom in           | Show the next longer / shorter period |
| =<= / =>= | move timeline backward / forward | |
| =. =  | =org-dayflow-offset-reset=     | Back to where the period starts |

Weekend columns get a subtle background, on the periods drawn a day to a column, when =org-dayflow-column-bands= is non-nil.

Query presets (via =/ s=): open+dated (default), all dated including done, open only, done only, unit at point, scheduled, deadline.
Atoms include =(done)= and =(on-day MONTH DAY YEAR)=.

** Headings and their children

A heading with rows under it is drawn as a line across the dates of its whole
subtree, from the first date anywhere under it to the last.  The heading needs
no date of its own; the work under it has them.

: ▾執行会議付議 ──────────────────
:  *資料の骨子
:              *部門長レビュー
:                        *修正版の提出

Folded, the steps go and the line stays, with a ◆ on every deadline in the
subtree -- which is what a month is read for: where each piece of work runs and
where it is due.

: ▸執行会議付議 ────────────◆──

- A heading is shown when it or anything under it matches the query, so a
  matching task arrives with the work it belongs to.
- The line is worked out from the whole subtree, matching or not, so it does
  not shrink as steps are done and filtered away.
- The sparkline counts the tasks, not the headings, so nothing is counted twice.
- A task without rows under it is drawn as before, at its own date.

=org-dayflow-visible-depth= (default 2) is how many levels a new view shows;
=S-TAB= cycles it, and =TAB= folds or opens one row.

** Customization

#+begin_src emacs-lisp
;; Window behavior identical to org-agenda
(setq org-dayflow-window-setup 'reorganize-frame
      org-dayflow-restore-windows-after-quit t)

;; Show only top-level headings at first (nil shows everything)
(setq org-dayflow-visible-depth 1)

;; Compact rendering
(setq org-dayflow-high-density t)

;; Shade Sat/Sun columns where a column is a day (single face; nil to disable)
(setq org-dayflow-column-bands t)

;; Default query is open+dated; include done via `/ s' -> "all dated (include done)"
;; (setq org-dayflow-initial-query
;;       '((or (scheduled) (deadline) (regexp org-ts-regexp))))

;; What each period is made of, and how much of it is already behind you.
;; The offsets are a share of the period rather than a count of columns,
;; because the number of columns follows the window.
(setq org-dayflow-spans '((month day 26) (quarter week 14) ...)
      org-dayflow-default-offsets '((month . -0.25) (quarter . -0.25) ...))

;; Files the agenda reads and the timeline should not: a calendar mirrored
;; into Org draws every weekly meeting as a row of the same mark.  A function
;; is called for the name, for a file whose name is decided at run time.
(setq org-dayflow-exclude-files '("~/org/calendar.org"))
#+end_src

See =M-x customize-group RET org-dayflow RET= for the full list.

** Looking at it before configuring anything

: M-x org-dayflow-demo-mode

Generates a few weeks of work in a directory of its own, points
=org-agenda-files= at it, declares the keywords and category colours the
generated files are written in, and opens the view. Switching it off puts the
files back and kills the Dayflow buffers — the buffer is named for its period
and not for where its rows came from, so a demo left on the screen is a month
nobody could tell from their own.

The dates are computed from today rather than written down, and one piece of
work sits past the edge of each period, so stepping out to a longer one always
reveals something. =M-x org-dayflow-demo-regenerate= is the way back after
moving things about in the view.

** Comparison with Similar Tools

- =org-agenda=: more powerful and general, table-oriented, huge feature surface.
- =org-ql-view=: excellent query power and listing; org-dayflow focuses on the visual "flow" across days.
- org-dayflow tries to stay small, depend only on Org, and reuse the same design patterns (window setup, remote edit, markers, follow mode, etc.) that =org-agenda= uses.
